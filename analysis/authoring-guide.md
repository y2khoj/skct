# SKCT 문제 분석·출제 인수인계

## 현재 상태 (2026-09-20)

- 299문항, 보기 1,495개, 공통 지문 2개를 문항 ID로 분리했다.
- 정답은 `answer_option_id`로 보기와 연결한다. 표시용 정답 문장과 OMR 번호를 별도로 수기 관리하지 않는다.
- 언어이해 48, 자료해석 30, 언어추리 96, 수열추리 40, 응용수리·경우의 수 85문항이다.
- 원본에서 번호를 분리할 수 있는 해설 182개를 텍스트로 추출했다. 손글씨·주석 해설은 원본 열기로 확인한다.
- 표의 유니코드 텍스트와 선, 분수의 분자·분모 위치는 SVG로 보존했다. 이미지 표 9개는 행·열 데이터로 직접 전사했다. 지도·산점도·좌석 배치 등의 비텍스트 그림은 필요한 경우 원본 그림을 유지하고 설명을 붙였다.
- 정답 번호는 원본 정답표와 대조했지만 모든 문제를 독립적으로 다시 풀어 정답의 유일성까지 증명한 것은 아니다. `generation_ready`는 전부 false이다. 이것은 자료 준비 상태와 출제 검증 완료 상태를 구분하기 위한 값이다.

## 편집과 빌드

기준 파일은 `data/question-bank.json`이다. 각 항목은 `id`, `stem`, `context`, `options`, `answer_option_id`, `source`, `analysis`를 가진다. 텍스트 문제의 수정은 이 파일에서 한다.

1. 문제·보기 문장을 고친다. 기존 학습 기록을 연결하려면 ID를 유지한다.
2. 정답을 바꿀 때에는 정답인 보기의 ID를 `answer_option_id`에 지정한다. 변경 근거와 검증 결과를 기록하고 `answer_source`를 원본 정답표로 오인하지 않게 바꾼다.
3. `layout_mode: spatial_text`의 도형·표 텍스트는 `context_svg`가 화면에 표시된다. 해당 자료를 변경할 때 SVG 또는 `tables`까지 함께 수정한다. 새 문제는 가능한 한 `structured`와 `tables`를 사용한다.
4. `node build-question-bank.cjs`로 브라우저 JS와 읽기용 Markdown을 생성한다.
5. `node --test training-core.test.cjs data-mapping.test.cjs question-bank.test.cjs`를 실행한다. 원본과 의도적으로 다르게 만든 새 문항은 원본 정답 대조 테스트와 별도의 생성 문제 검증을 구분해야 한다.
6. `text-render.test.html`에서 렌더링과 선택·정답 표시를 확인한다.

`extract_question_bank.py`는 원본 PDF에서 초기 자료를 다시 추출하는 도구다. 평소 편집 후에는 위 빌드 명령을 쓴다. 추출을 다시 실행하면 JSON 직접 편집이 덮어써지므로 전사 보정은 `data/text-overrides.json`에도 보관한다. PDF 암호는 `SKCT_PDF_PASSWORD` 환경변수로 전달하며 저장소에는 기록하지 않는다.

## 발견한 원본·연결 주의점

1. 자료해석 30번의 보기는 문제 PDF 84페이지의 이미지다. 기존 앱에는 이 페이지가 빠져 있었다. 5개 보기의 도표 정보를 직접 읽어 복원했고 `source.question_pages`에 83, 84를 기록했다.
2. 자료해석 15번은 마지막 보기 기호가 ⑥으로 되어 있다. 총 다섯 보기이므로 선택 번호 5로 정규화했다. 보기 내용은 유지했다.
3. PSAT 8·9번 및 12·13번은 별도 공통 지문을 반드시 함께 제공해야 한다. 무작위 출제에서도 문항의 `passage_id`를 따라 표시한다.
4. 수열 31·34·36번 등 분수의 줄바꿈을 단순 이어 붙이면 수가 바뀐다. 분수 보기는 `11/4`와 같이 직렬화하고 문제의 분수 배치는 보존했다.
5. 자료해석 14번 산점도는 각 점의 정확한 좌표 숫자가 표기되지 않았다. 그림을 보고 임의의 정확한 수치로 채워 출제용 데이터라고 취급하지 않는다.
6. 원본 명제추리에는 집합의 존재를 암묵적으로 가정하는 풀이가 있다. 새 문제에서는 이 가정을 조건에 명시하거나 존재명제 추론을 요구하지 않는다.
7. 훈련실의 응용수리는 기존 페이지 단위 수동 점검 통계를 유지한다. 텍스트 보기 선택과 정답 대조는 가능하며, 시험 화면은 개별 보기 ID로 채점한다.

## 확인한 작은 검산 사례

- 응용수리 1번: (0.10×60 + 0.20×180) ÷ (60+180) ×100 = 17.5%. 보기 3과 일치한다.
- 응용수리 2번: 소금 6+27=33g, 증발 후 240g이므로 13.75%. 보기 4와 일치한다.
- 수열 23번: 검정 화살표가 1→4→7→10시, 빈 화살표가 1→5→9→1시로 이동한다. 보기 1과 일치한다.
- 수열 24번: 검정 화살표는 12→2→4→6시, 빈 화살표는 1→3→6→10시로 이동한다. 보기 3과 일치한다.

이 네 사례는 해당 문제의 간단한 검산이다. 전체 은행이나 새로운 출제기의 유일 정답 검증으로 확대해 해석하지 않는다.

## 다음 출제 작업에서 이어갈 일

원하는 유형과 난이도가 정해지면 해당 유형 5~10문항을 먼저 독립적으로 풀어 풀이 구조와 오답 원인을 보강한다. 변수 범위와 제약을 문서화하고, 생성된 문제를 정답 산출 코드와 별도의 검증 코드로 확인한다. 실제 정답률·풀이시간이 쌓이면 그 근거로 난이도를 조정한다. 새로 확인한 내용은 이 문서와 문항별 `analysis`에 누적한다.
